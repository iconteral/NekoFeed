# 指标口径与交付验收

## 1. 曝光统计口径

一次曝光需同时满足：

1. Feed 卡片进入 `LazyColumn` 可见区域。
2. 可见像素高度 / 卡片总高度 `>= 50%`。
3. 同一 App 页面会话中，该 `itemId` 尚未记过曝光。

事件包含内容 ID、事件类型、时间戳、会话 ID、运行环境、标题、图片、分类和内容类型。`mock` 与真实服务器环境隔离，避免演示数据污染真实统计。

当前口径未加入最短停留时长，因此它表达“有效进入视区”，不等同于广告行业严格的可见曝光标准。若用于生产，应增加持续时间、前后台状态、遮挡判断和服务端去重。

## 2. 其他事件口径

| 事件 | 触发条件 |
| --- | --- |
| click | 用户进入详情、CTA 或原文等有效跳转动作 |
| play | Media3 实际进入播放态，每次卡片播放生命周期只报一次 |
| like | 点赞操作成功并获得权威状态 |
| collect | 收藏操作成功并获得权威状态 |
| share | 用户触发系统分享流程 |

CTR 公式：`click / exposure`；曝光为 0 时返回 0。排行数据直接由事件流水按 `itemId` 分组聚合，可选择曝光、点击或播放指标。

## 3. 自动化验证

覆盖的关键规则：

- 视频频道能匹配视频卡片。
- 电商频道只匹配商品/广告，不误收普通文章。
- 取消点赞后从点赞列表移除。
- 收藏数使用服务端权威值。
- 事件聚合能正确计算曝光、点击、播放、互动、内容去重和 CTR。
- 排行切换曝光/点击/播放时返回对应指标。

## 5. 性能材料说明

本交付包含代码级性能策略和可构建 APK，但未提供未经规范采样的 FPS、启动耗时或网络延迟对比。建议后续固定设备、Build Variant、数据量和网络条件，使用 Macrobenchmark、Baseline Profile、Perfetto 与服务端压测分别采集：

- 冷/热启动 P50、P95
- Feed 滚动慢帧与卡顿帧比例
- 20/100/500 条内容下的内存峰值
- 图片有无缓存的加载耗时
- AI 并发限制前后的首批结果耗时、错误率和请求量
- RSS 刷新和 `/api/feed` 的吞吐与 P95

只有在相同采样条件下得到的数据才适合做性能对比。
