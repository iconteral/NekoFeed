# AI 广告推荐信息流 App 设计大纲

## 1. 产品定位

项目名称暂定为 **NekoFeed AI / 灵动广告流**。

本 App 面向“内容与广告混排”的推荐场景，目标是实现一个类似今日头条、抖音精选页、信息流广告页的单列广告推荐 App。用户可以在不同频道中浏览广告内容，查看图文或视频详情，进行点赞、收藏、分享等互动，并通过 AI 摘要、智能标签和对话式搜索提升广告内容的可读性与可发现性。

核心目标不是做一个真正的商业广告平台，而是展示以下能力：

1. 单列信息流的流畅展示与状态保持。
2. 多类型广告卡片的动态渲染。
3. 视频播放资源复用与列表生命周期管理。
4. 本地模拟曝光、点击、互动等埋点数据。
5. 使用大模型生成广告摘要、标签，并支持自然语言搜索。

---

## 2. 整体设计风格

### 2.1 UI 风格

采用 **Material Design 3**，整体风格偏“现代内容消费 App”：

* 背景：浅色模式为主，支持深色模式作为加分项。
* 卡片：圆角、大图、轻阴影，突出广告创意素材。
* 颜色：主色建议使用蓝紫色或橙红色，体现“智能推荐”和“广告营销”的感觉。
* 字体层级：标题突出，摘要简洁，标签轻量化。
* 动效：页面切换、点赞、收藏、Tab 切换、加载 Skeleton。

### 2.2 设计关键词

* **信息密度适中**：广告卡片不能太拥挤。
* **AI 感知明显**：摘要、标签、搜索入口要让用户看到 AI 能力。
* **答辩可解释**：每个设计都能对应一个技术点，例如列表复用、播放器复用、状态同步、曝光统计。
* **两周可落地**：优先保证核心功能，AI 与动画做成可选增强。

详情页用于展示广告完整信息和互动状态。

### 6.1 页面结构

```text

│ 返回按钮        品牌名          │
├──────────────────────────────┤
│ 大图 / 视频播放器              │
├──────────────────────────────┤
│ 广告标题                      │

│ 智能标签 Chips                 │
│ 原始广告描述                  │
├──────────────────────────────┤
│ 点赞 / 收藏 / 分享 / 查看统计   │
└──────────────────────────────┘
```

### 6.2 状态同步

详情页和首页共享同一份广告状态：

* 在详情页点赞，返回首页后卡片点赞状态同步。
* 在详情页收藏，首页卡片状态同步。
* 进入详情页时增加点击次数。
* 详情页播放视频时，首页对应视频卡片暂停。

推荐实现方式：

* `AdRepository` 作为单一数据源。
* `FeedViewModel` 和 `DetailViewModel` 都通过 Repository 读取广告状态。
* 点赞、收藏、点击统计等操作统一写回 Repository。
* Repository 内部使用 `MutableStateFlow<List<AdItem>>` 管理数据。

## 7. 对话式搜索 SearchScreen 设计

这是可选功能，但非常适合答辩加分。

### 7.1 页面定位

用户不通过关键词搜索，而是用自然语言描述想看的广告，例如：

* “我想看适合学生党的平价耳机”
* “有没有适合周末出游的广告”
* “推荐一些运动健身相关的内容”
* “找本地餐饮优惠”

### 7.2 页面结构

```text
┌──────────────────────────────┐
│ 返回按钮   AI 对话搜索          │
├──────────────────────────────┤
│ 用户输入框：描述你想看的广告     │
│ 搜索按钮                       │
├──────────────────────────────┤
│ AI 理解结果：                  │
│ 关键词：学生党、平价、耳机       │
│ 匹配标签：#性价比 #数码         │
├──────────────────────────────┤
│ 搜索结果列表                   │
└──────────────────────────────┘
```

### 7.3 搜索实现方案

两周内推荐使用“轻量级语义搜索”：

第一阶段：

* 从用户输入中提取关键词。
* 和广告标题、摘要、标签进行本地匹配。
* 按匹配分数排序。

第二阶段：

* 调用大模型，把用户输入转换为结构化查询：

```json
{
  "keywords": ["学生党", "耳机", "平价"],
  "tags": ["数码", "性价比"],
  "scene": "通勤/学习"
}
```

第三阶段：

* 根据结构化结果过滤广告。
* 返回匹配结果。
* 如果模型调用失败，则降级为本地关键词搜索。

## 8. AI 摘要与智能标签设计

### 8.1 AI 能力目标

每条广告生成：

1. 一句话摘要：用于卡片副标题。
2. 智能标签：用于展示和过滤。
3. 可选推荐理由：用于详情页或搜索结果。

示例：

```json
{
  "summary": "适合学生和通勤人群的高性价比降噪耳机。",
  "tags": ["数码", "学生党", "性价比", "通勤"],
  "reason": "价格友好，主打降噪和长续航，适合日常学习与出行。"
}
```

### 8.2 AI 输出约束

为了避免大模型输出不可控，Prompt 要求必须返回 JSON：

```text
你是广告内容理解助手。
请根据广告标题、品牌、描述，生成结构化 JSON。
只能返回 JSON，不要输出解释文字。
字段包括 summary、tags、reason。
tags 最多 4 个，每个标签不超过 5 个字。
summary 不超过 30 个字。
```

### 8.3 AI 缓存策略

AI 结果不应每次进入页面都重新生成。

缓存策略：

* 以 `adId` 作为 key。
* 首次加载广告时，如果无 AI 结果，则请求模型。
* 成功后写入本地缓存。
* 下次进入页面优先读取缓存。
* 模型失败时使用规则生成的摘要和标签兜底。

本地可先使用内存缓存，进阶可以使用 DataStore 或 Room。

## 9. 埋点统计设计

### 9.1 统计指标

需要模拟以下指标：

* 曝光次数 `exposureCount`
* 点击次数 `clickCount`
* 点赞次数 `likeCount`
* 收藏次数 `collectCount`
* 分享次数 `shareCount`
* 视频播放次数 `playCount`

### 9.2 曝光统计口径

建议定义为：

> 当广告卡片可见面积超过 50%，并且停留时间超过 1 秒，记为一次有效曝光。

两周内实现可以简化为：

* 使用 `LazyListState.layoutInfo.visibleItemsInfo` 获取当前可见 item。
* 当 item 首次进入可见区域时，记录曝光。
* 同一个广告在同一次会话中只统计一次曝光。
* 可在技术文档中说明真实业务中应加入可见面积和停留时长判断。

### 9.3 统计展示页 StatsScreen

页面结构：

```text
┌──────────────────────────────┐
│ 数据统计                       │
├──────────────────────────────┤
│ 总曝光：xxx                    │
│ 总点击：xxx                    │
│ 总点赞：xxx                    │
│ CTR：点击 / 曝光               │
├──────────────────────────────┤
│ 广告排行：                     │
│ 1. 某耳机广告 曝光 30 点击 8    │
│ 2. 某美食广告 曝光 25 点击 5    │
└──────────────────────────────┘
```

该页面非常适合答辩展示，因为它能证明“埋点统计”不是只写了代码，而是有可视化结果。

## 13. 性能与资源复用设计

### 13.1 列表性能

策略：

* 使用 `LazyColumn`。
* 为 `items` 设置稳定 key：`key = { it.id }`。
* 卡片组件拆分，避免单个 Composable 过大。
* 图片使用 Coil 加载。
* 对列表状态使用 `rememberLazyListState`。
* 返回详情页时不重建 FeedViewModel。
* 避免在 Composable 中直接执行耗时逻辑。

### 13.2 图片缓存

使用 Coil 完成图片加载与缓存。

策略：

* 首屏图片优先加载。
* 卡片图片使用占位图。
* 加载失败显示降级 UI。
* 图片尺寸尽量与卡片尺寸匹配，避免加载超大图。
* 可选：对下一屏图片做预加载。

### 13.3 视频播放器复用

使用 Media3 ExoPlayer。

推荐策略：

* 不为每个视频卡片创建一个播放器。
* 使用 `PlayerManager` 管理单个或少量播放器实例。
* 当前只有一个视频处于播放状态。
* 视频卡片进入播放时，绑定播放器。
* 视频卡片离开屏幕时，暂停并释放绑定。
* 页面销毁时释放播放器资源。

```text
FeedScreen
    ↓
VideoAdCard
    ↓ 请求播放
PlayerManager
    ↓
复用 ExoPlayer 实例
```

## 16. 降级方案设计

为了防止 AI 接口不可用，必须设计降级方案。

### 16.1 AI 摘要降级

如果大模型不可用：

* 使用广告描述前 30 个字作为摘要。
* 根据关键词规则生成标签。

例如：

```text
标题/描述包含“耳机、手机、相机” → 数码
包含“学生、平价、优惠” → 性价比 / 学生党
```

## 21. 项目亮点总结

本项目的亮点可以概括为：

1. **动态广告卡片**：通过数据字段控制卡片样式，实现大图、小图、视频广告混排。
2. **高性能信息流**：使用 LazyColumn、稳定 key、图片缓存和状态保持优化滚动体验。
3. **播放器资源复用**：通过 PlayerManager 控制单播放器实例，避免列表中多个视频同时占用资源。
4. **AI 内容理解**：使用大模型生成广告摘要和标签，提升广告可读性。
5. **对话式搜索**：用户可以用自然语言描述想看的广告，提高广告发现效率。
6. **埋点可视化**：本地模拟曝光、点击、互动数据，并在统计页展示。
7. **完整降级方案**：AI、视频、图片加载失败时均有兜底逻辑，保证 App 稳定运行。
